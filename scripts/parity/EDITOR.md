# The editor: pi's editor against the port's, behaviour by behaviour

The editor is the component the user touches on every message. This is the
comparison of pi's editor with the port's: one row per behaviour, pi's rule, the
port's rule, whether they agree, and the file:line on both sides. The rows the
port has and pi does not are in the tables too, so the list is the whole truth
and not only the differences.

The file is regenerated by its harness:

```
node scripts/parity/editor-parity.mjs --write --test
```

The harness parses every row, counts the statuses, rewrites the summary below
and **fails when a row still differs and is not signed off** in
`SIGN-OFF.md`. A difference is either fixed or signed off, never forgotten.

The port's own extras, which pi has no counterpart for: a **text selection**
inside the editor (Shift+arrows, Ctrl+X/Ctrl+V, typing over the selection), a
**redo** command and stack, a **placeholder**, an **End / Ctrl+E** line-end
binding, and a **Ctrl+X / Ctrl+V** cut-and-paste on the kill ring. They are
listed in `SIGN-OFF.md` §19.

### Fixed in this pass

* **The keybinding registry** — every editor key now goes through
  `kb.matches(&key, "tui.editor.…")` (`editor.rs:2127-2360`), so a rebind in
  `settings.json` works and pi's defaults (Ctrl+B/Ctrl+F for the arrows,
  Ctrl+A for the line start, PageUp/PageDown for the page) are honoured.
* **The caret and the column** — the arrows step by **grapheme** (a ZWJ emoji
  or a combining mark is one step), and the vertical movement is measured in
  **visual** lines with pi's sticky column, so a wrapped line scrolls like
  pi's and a short line no longer loses the column.
* **The history** — the editor owns it now (`add_to_history`,
  `navigate_history`), the app records the entries through it, the browse mode
  keeps the caret of the draft, and an edit leaves the browse mode.
* **The undo** — fish-style coalescing (a snapshot on whitespace), a paste is
  one unit of its own, and the stack is unbounded, like pi's.
* **The kill ring** — the accumulation follows the *previous* action, so an
  edit breaks the chain; Ctrl+K/Ctrl+U/Ctrl+W/Alt+D join the lines at the
  line ends; the yank-pop replaces the yanked text instead of duplicating it;
  the ring is unbounded and keeps duplicates.
* **The selection** — a plain caret move no longer ends it (the span is the
  two ends of the selection, not the anchor and the caret), which was the
  reported complaint.
* **The paste and the submit** — a pasted path gets a leading space, the
  submitted text is trimmed, the editor is cleared before the callback runs,
  a bare LF is a newline, and a `\` before the caret turns the submit into a
  newline.
* **The wrap** — the port's `wrap_line_ranges` now breaks exactly where pi's
  `wordWrapLine` breaks, including the re-wrap of an over-wide paste marker.
* **The character jump** — `jump_to_char` searched the current line from
  `cursor_col ± 1` **bytes**, so it skipped the character right next to the
  caret and it searched the other lines from the wrong end. It now matches
  pi's `jumpToChar` (E:2349-2376): forward from `cursorCol + 1`, backward
  from `cursorCol - 1` (clamped at zero), the other lines whole, and the
  comparison in code units (`editor.rs:1991-2054`). The mode also no longer
  deadlocks: the jump flag was read with a `MutexGuard` that stayed alive
  across the `if let` body, and the body re-locked the same mutex, so the
  next key press hung the editor (`editor.rs:2262`).
* **The kill ring's duplicates** — the port dropped a duplicate entry; pi's
  ring keeps it (`packages/tui/src/kill-ring.ts:19-27`), so the port keeps
  them too (`kill_ring.rs:62-84`).

### How the rows are checked

The port's editor is measured against the original's **TypeScript** editor,
not against a description of it: a probe drives the original
(`packages/tui/src/components/editor.ts`) and the port through the same key
sequences and compares the text and the caret after every step. The
measurements are pinned by `editor.rs`'s
`the_editor_matches_the_originals_measured_sessions` test, one recorded
session per cluster (the vertical movement, the history, the undo, the kill
ring, the keybinding registry, the word moves and the submit).

### Still open

1. **The selection vs. the caret** — the editor still owns a selection pi does
   not have (Shift+arrows, Ctrl+X/Ctrl+V, typing over the selection), and an
   edit or an undo ends it. Signed off in `SIGN-OFF.md` §19.
2. **The caret's stored column** is a byte offset where pi's is a UTF-16
   code-unit index. Every place the original does arithmetic in code units is
   done in code units in the port, so the caret lands in the same place; the
   difference is in the public `cursor_position()` value only.
